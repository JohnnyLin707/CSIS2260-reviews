A process is a program in execution.

进程：正在执行的程序。

It is an instance of a program running on a computer, and the entity that can be assigned to and executed on a processor.

它是在计算机上运行的一个程序实例，是可以被指派到处理器上并执行的实体。

It is a unit of activity characterized by the execution of a sequence of instructions, a current state, and an associated set of system resources.

它是一个活动单位：由一串指令的执行、当前状态以及一组相关的系统资源来刻画。

A process has two essential elements: program code, and a set of data associated with that code (which may be shared with other processes running the same program).

进程有两个基本要素：程序代码，以及与该代码相关的一组数据（可与运行同一程序的其他进程共享）。

Source: “Ch03v2a.pdf” — original slides: p.4, p.33（点击链接可跳转查看原教材）

The process control block (PCB) holds the process elements; it is created and managed by the OS and is the key tool that allows support for multiple processes.

进程控制块（PCB）：保存进程的各个要素，由操作系统创建和管理，是支持多进程的关键工具。

Three PCB elements, for example: identifier, state and priority.

PCB 的三个要素（例如）：标识符、状态、优先级。

Other elements are: program counter, memory pointers, context data, I/O status information and accounting information.

其余要素还有：程序计数器、存储器指针、上下文数据、I/O 状态信息和记账信息。

The process image is the collection of program, data, stack and attributes of a process.

进程映像：进程的程序、数据、栈与属性的集合。

Three process image elements, for example: user data, user program and stack (each process has one or more LIFO stacks for parameters and calling addresses).

进程映像的三个要素（例如）：用户数据、用户程序、栈（每个进程有一个或多个后进先出栈，用于保存参数和调用地址）。

The fourth element is the process control block itself: the data the OS needs to control the process.

第四个要素就是进程控制块本身：操作系统控制进程所需的数据。

Source: “Ch03v2a.pdf” — original slides: p.6, p.33, p.34（点击链接可跳转查看原教材）

A trace is the behaviour of an individual process, shown by listing the sequence of instructions that execute for that process.

轨迹（trace）：通过列出某个进程所执行的指令序列来刻画该进程的行为。

The behaviour of the processor can be characterized by showing how the traces of the various processes are interleaved.

处理器的行为可以通过展示各进程的轨迹如何交错来刻画。

The dispatcher is the small program that switches the processor from one process to another; it appears at the switching points between the traces.

分派程序（dispatcher）：把处理器从一个进程切换到另一个进程的小程序，出现在各轨迹的交错点上。

Source: “Ch03v2a.pdf” — original slides: p.8（点击链接可跳转查看原教材）

1. New batch job: the OS reads the next sequence of job control commands when it is prepared to take on new work.

1. 新的批处理作业：操作系统准备接受新工作时，读入下一段作业控制命令。

2. Interactive logon: a terminal user logs on to the system.

2. 交互式登录：终端用户登录到系统。

3. Created by the OS to provide a service: the OS creates a process to perform a function on behalf of a user program.

3. 操作系统为提供服务而创建：操作系统代表用户程序创建进程来完成某项功能。

4. Spawned by an existing process: for modularity or to exploit parallelism, a user program can dictate the creation of new processes; the original creating process is the parent and the new process is the child.

4. 由已有进程派生：出于模块化或利用并行性，用户程序可以要求创建新进程；发起创建的进程是父进程，新进程是子进程。

Source: “Ch03v2a.pdf” — original slides: p.14, p.15（点击链接可跳转查看原教材）

1. Normal completion: the process executes an OS service call (or a HALT instruction in a batch job) to indicate that it has completed running.

1. 正常完成：进程执行操作系统的服务调用（批处理作业中是 HALT 指令）以表明自己已运行完毕。

2. Time limit exceeded: the process has run longer than the specified total time limit (total elapsed time, time spent executing, or time since the last user input).

2. 超过时限：进程运行时间超过了规定的总时限（总经过时间、执行时间，或距用户上次输入的时间）。

3. Memory unavailable: the process requires more memory than the system can provide.

3. 内存不足：进程需要的内存超过了系统能提供的数量。

Others: bounds violation, protection error, arithmetic error (for example division by zero), time overrun, I/O failure, invalid instruction, privileged instruction, data misuse, operator or OS intervention (for example a deadlock), parent termination and parent request.

其他还有：越界、保护错误、算术错误（例如除以零）、超时、I/O 故障、非法指令、特权指令、数据误用、操作员或操作系统干预（例如出现死锁）、父进程终止以及父进程请求。

Source: “Ch03v2a.pdf” — original slides: p.16（点击链接可跳转查看原教材）

New: the process has just been created but has not yet been admitted to the pool of executable processes.

新建态（New）：进程刚被创建，还没有被接纳进可执行进程池。

Ready: the process is in main memory and is prepared to run as soon as the processor is given to it.

就绪态（Ready）：进程已在主存中，一旦获得处理器就可以运行。

Running: the process is the one whose instructions are being executed by the processor.

运行态（Running）：进程的指令正在被处理器执行。

Blocked: the process cannot execute until some event occurs, for example the completion of an I/O operation.

阻塞态（Blocked）：进程必须等到某个事件发生（例如 I/O 操作完成）才能继续执行。

Ready/Suspend: a ready process that has been swapped out to disk; it can run as soon as it is loaded back into main memory.

就绪/挂起态：一个就绪进程被换出到磁盘；一旦调回主存就可立即运行。

Blocked/Suspend: a blocked process that has been swapped out to disk; it is still waiting for its event.

阻塞/挂起态：一个被阻塞的进程被换出到磁盘；它仍在等待自己的事件。

Exit: the process has halted or aborted and has been released by the operating system.

退出态（Exit）：进程已停止或被中止，并被操作系统释放。

Admit: New to Ready. Dispatch: Ready to Running. Timeout: Running back to Ready when the time slice ends.

接纳（Admit）：新建 → 就绪。分派（Dispatch）：就绪 → 运行。超时（Timeout）：时间片用完，运行 → 就绪。

Event Wait: Running to Blocked. Event Occurs: Blocked back to Ready. Release: Running to Exit.

事件等待（Event Wait）：运行 → 阻塞。事件发生（Event Occurs）：阻塞 → 就绪。释放（Release）：运行 → 退出。

Suspend: Ready to Ready/Suspend and Blocked to Blocked/Suspend (swapping). Activate: Ready/Suspend back to Ready and Blocked/Suspend back to Blocked.

挂起（Suspend）：就绪 → 就绪/挂起，阻塞 → 阻塞/挂起（通过交换换出）。激活（Activate）：就绪/挂起 → 就绪，阻塞/挂起 → 阻塞。

Source: “Ch03v2a.pdf” — original slides: p.22, p.23（点击链接可跳转查看原教材）

Memory tables: keep track of both main (real) and secondary (virtual) memory; processes are maintained on secondary memory using virtual memory or simple swapping.

存储器表：跟踪主存（实存）与二级存储器（虚存）；通过虚拟存储器或简单的交换机制把进程保存在二级存储器上。

I/O tables: used to manage the I/O devices and channels; at any given time a device may be available or assigned to a particular process.

I/O 表：用于管理 I/O 设备与通道；任一时刻设备可能是可用的，也可能已分配给某个特定进程。

File tables: information about the existence of files, their location on secondary memory, their current status and other attributes.

文件表：记录文件是否存在、在二级存储器上的位置、当前状态和其他属性。

Process tables: the primary process table manages the processes themselves; it must contain some reference to memory, I/O and files, directly or indirectly.

进程表：主进程表管理进程本身，必须直接或间接地包含对内存、I/O 和文件的某种引用。

Source: “Ch03v2a.pdf” — original slides: p.27, p.28, p.29, p.30, p.31（点击链接可跳转查看原教材）

Processor state information consists of the contents of the processor registers.

处理器状态信息：由处理器寄存器的内容组成。

A good example is the program status word (PSW): it contains condition codes plus other status information, for example the overflow flag, the sign flag and the interrupt enable flag.

一个典型例子是程序状态字（PSW）：它包含条件码及其他状态信息，例如溢出标志、符号标志和中断允许标志。

Other examples are user-visible registers, control and status registers, the program counter and the stack pointers.

其他例子还有：用户可见寄存器、控制与状态寄存器、程序计数器以及栈指针。

This information is saved when the process is interrupted so that it can later be resumed as if the interruption had not occurred.

进程被中断时要保存这些信息，之后才能恢复执行，就好像中断从未发生过一样。

Source: “Ch03v2a.pdf” — original slides: p.37, p.40（点击链接可跳转查看原教材）

User mode: the less-privileged mode; user programs typically execute in this mode.

用户态：特权较低的模式；用户程序通常在该模式下执行。

System mode: the more-privileged mode; it is also referred to as control mode or kernel mode, and it is the mode in which the kernel of the operating system runs.

系统态：特权更高的模式，也称为控制态或内核态，操作系统内核在该模式下运行。

In kernel mode privileged instructions may be executed and protected areas of memory may be accessed; in user mode they may not.

在内核态下可以执行特权指令、访问受保护的内存区域；在用户态下则不可以。

The processor enters kernel mode when an interrupt occurs, when an exception (trap) is generated, or when a system call (supervisor call) is issued.

处理器在发生中断、产生异常（陷阱）或发出系统调用（管态调用）时进入内核态。

Source: “Ch03v2a.pdf” — original slides: p.45（点击链接可跳转查看原教材）

Inside the kernel — process management: process creation and termination, process scheduling and dispatching, process switching, process synchronization and support for interprocess communication, management of process control blocks.

内核内的进程管理：进程的创建与终止、进程的调度与分派、进程切换、进程同步及对进程间通信的支持、进程控制块的管理。

Inside the kernel — memory management: allocation of address space to processes, swapping, page and segment management.

内核内的存储器管理：为进程分配地址空间、交换、页式与段式管理。

Inside the kernel — I/O management and support functions: buffer management, allocation of I/O channels and devices to processes, interrupt handling, accounting and monitoring.

内核内的 I/O 管理与支撑功能：缓冲区管理、把 I/O 通道与设备分配给进程、中断处理、记账与监视。

Outside the kernel: the command interpreter (shell) and the system utilities a user calls from the command line.

内核之外：命令解释程序（shell）以及用户在命令行调用的系统实用程序。

Outside the kernel: file system and print services, which in a microkernel are ordinary server processes.

内核之外：文件系统与打印服务，在微内核结构中它们只是普通的服务器进程。

Outside the kernel: network protocols and device drivers, which can execute within user processes or as separate processes (Figure 3.15 b and c); a microkernel assigns only a few essential functions to the kernel.

内核之外：网络协议与设备驱动程序，它们可以在用户进程内执行，或作为独立进程执行（图 3.15 b、c）；微内核只把少数最基本的功能留给内核。

Source: “Ch03v2a.pdf” — original slides: p.46, p.52（点击链接可跳转查看原教材）

Once the OS decides to create a new process it assigns a unique process identifier to the new process.

操作系统一旦决定创建新进程，首先为新进程分配唯一的进程标识符。

Allocates space for the process: the whole process image (program, data, stack and attributes).

为进程分配空间：即整个进程映像（程序、数据、栈与属性）。

Initializes the process control block.

初始化进程控制块。

Sets the appropriate linkages: for example putting the PCB into the ready queue or into the process list.

建立相应的链接：例如把 PCB 放入就绪队列或进程链表中。

Creates or expands other data structures: for example the memory, I/O and file tables that the OS keeps for the process.

创建或扩充其他数据结构：例如操作系统为该进程维护的存储器表、I/O 表和文件表。

Source: “Ch03v2a.pdf” — original slides: p.47（点击链接可跳转查看原教材）

Interrupt: external to the execution of the current instruction; a reaction to an asynchronous external event such as a clock interrupt, an I/O interrupt or a memory fault.

中断（Interrupt）：产生于当前指令执行之外，是对异步外部事件的反应，例如时钟中断、I/O 中断或存储器故障。

Trap: associated with the execution of the current instruction; it handles an error or an exception condition generated within the currently running process (for example division by zero).

陷阱（Trap）：与当前指令的执行相关，用于处理当前运行进程内部产生的错误或异常状况（例如除以零）。

For a trap the OS determines whether the condition is fatal; if it is fatal, the process is moved to the Exit state and a process switch occurs.

对陷阱，操作系统会判断该状况是否致命；若致命，进程被移入退出态并发生进程切换。

Supervisor call: an explicit request, a call to an operating system function made by the program itself.

管态调用（Supervisor call）：程序自己发出的明确请求，即调用操作系统的某个功能。

All three give control to the OS, so a process switch may occur whenever the OS has gained control from the currently running process.

三者都会把控制权交给操作系统，因此只要操作系统从当前运行进程取得控制权，就可能发生进程切换。
