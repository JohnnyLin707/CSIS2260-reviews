Q19 Briefly explain what the ISA, ABI and API of a computer system are.简要说明计算机系统的 ISA、ABI 与 API 分别是什么。 ▾

ISA (instruction set architecture): the set of machine instructions and registers the hardware can execute; it is the border between hardware and software.

ISA（指令集体系结构）：硬件能够执行的机器指令与寄存器的集合，是硬件与软件的分界线。

ABI (application binary interface): the binary-level interface, for example system calls, data types, calling conventions; it lets a compiled program run on that system.

ABI（应用程序二进制接口）：二进制层面的接口，例如系统调用、数据类型、调用约定，使编译好的程序能在该系统上运行。

API (application programming interface): the set of functions a programmer calls in the source code to ask the operating system for a service, for example Win32 or POSIX.

API（应用程序编程接口）：程序员在源代码中调用的一组函数，用来向操作系统请求服务，例如 Win32 或 POSIX。

New hardware appears, for example new processors, multicore chips, new devices and new memory technology.

出现了新硬件，例如新处理器、多核芯片、新设备和新的存储技术。

用户需要新的服务和新的功能。

Errors and weaknesses must be fixed, and performance and resource use must be improved.

必须修正错误和缺陷，并改进性能与资源利用。

New threats appear, so better security and protection are needed.

新的威胁不断出现，因此需要更强的安全与保护。

Q21 Operating systems evolved from serial processing over simple batch systems and multiprogrammed batch systems to time sharing systems. Briefly explain the main problems of each system, and how the next one overcame it.操作系统从串行处理、简单批处理、多道程序批处理发展到分时系统。请说明各系统的主要问题，以及后一种系统如何解决。 ▾

Serial processing: there was no operating system; the operator set up each job by hand and the processor was idle during the long setup time.

串行处理：没有操作系统，操作员手工准备每个作业，很长的准备时间里处理器一直空闲。

Simple batch system: a monitor program runs jobs one after another, so setup is automatic; but the processor is still idle while the job waits for slow I/O.

简单批处理系统：监控程序自动把作业一个接一个地运行，省去手工准备；但作业等待慢速 I/O 时处理器仍然空闲。

Multiprogrammed batch system: several jobs are kept in memory, so when one job waits for I/O the processor runs another; the processor is used much better, but the user cannot talk with the job.

多道程序批处理系统：内存中同时存放多个作业，一个作业等 I/O 时处理器就运行另一个，处理器利用率大大提高；但用户无法与作业交互。

Time sharing system: many users get a small time slice each, so every user gets a fast answer and can work interactively.

分时系统：给每个用户分配很小的时间片，每个用户都能很快得到响应，可以交互工作。

Q22 In batch systems, what is JCL, and what is it used for?在批处理系统中，什么是 JCL？它用来做什么？ ▾

JCL stands for job control language.

JCL 即作业控制语言（job control language）。

It is a special language that describes the steps of a job for the operating system.

它是一种专门的语言，用来向操作系统描述一个作业的执行步骤。

It tells the system which compiler to use, which files to read and write and what program to run.

它告诉系统使用哪个编译器、读写哪些文件、运行哪个程序。

Q23 In batch systems, why is it desirable to have a processor with: a. Memory protection? b. Timers? c. Privileged instructions? d. Interrupts?在批处理系统中，为什么希望处理器具备：a. 存储器保护？ b. 定时器？ c. 特权指令？ d. 中断？ ▾

a. Memory protection: so one user job cannot change the memory of the monitor or of another job.

a. 存储器保护：防止一个用户作业修改监控程序或其他作业的内存。

b. Timers: so one job cannot run forever and keep the processor for itself.

b. 定时器：防止某个作业无休止运行、独占处理器。

c. Privileged instructions: only the operating system may execute them, so a user job cannot do dangerous things such as direct I/O.

c. 特权指令：只有操作系统能执行，使用户作业无法做危险操作，例如直接进行 I/O。

d. Interrupts: they give control back to the operating system quickly, for example when I/O finishes or an error happens, so the OS can switch to another job.

d. 中断：能让操作系统迅速收回控制权，例如 I/O 完成或出错时，从而切换到另一个作业。

Q24 What is the difference between user mode and kernel mode?用户态与内核态有什么区别？ ▾

User mode is the less privileged mode; user programs normally run in it.

用户态是特权较低的模式，用户程序通常在此运行。

In user mode the program cannot execute privileged instructions and cannot touch protected memory.

在用户态下程序不能执行特权指令，也不能访问受保护的内存。

Kernel mode (system mode, control mode) is the more privileged mode; the kernel of the operating system runs in it and may do everything.

内核态（系统态、控制态）是特权更高的模式，操作系统内核在此运行，可以做任何事情。

The mode changes when an interrupt, an exception or a service call happens.

当发生中断、异常或服务调用时，模式就会切换。

Q25 Briefly describe how multiprogramming improves computer performance compared to uniprogramming.与单道程序设计相比，多道程序设计如何提高计算机性能？ ▾

In uniprogramming only one job is in memory; while it waits for I/O the processor does nothing.

单道程序设计时内存中只有一个作业，它等待 I/O 期间处理器什么也不做。

In multiprogramming several jobs are in memory; when one waits for I/O the processor runs another job.

多道程序设计时内存中有多个作业，一个作业等 I/O 时处理器就运行另一个作业。

So the processor, the memory and the I/O devices are all used more of the time, and the throughput is higher.

因此处理器、存储器和 I/O 设备的使用时间都更长，吞吐量更高。

Q26 In contrast to batch systems, what is the main focus of time sharing systems?与批处理系统相比，分时系统的主要目标是什么？ ▾

The main focus is the response time of the interactive user.

主要目标是交互用户的响应时间。

The system must answer each user quickly, so it gives every user a small time slice in turn.

系统必须很快回答每个用户，因此轮流给每个用户很小的时间片。

Batch systems instead try to use the processor as much as possible and to maximise throughput.

批处理系统则尽量让处理器满负荷工作、最大化吞吐量。

Q27 In a modern operating system, what is a process?在现代操作系统中，什么是进程？ ▾

A process is a program in execution.

进程就是正在执行的程序。

It is an instance of a running program, and the entity that can be assigned to and executed on a processor.

它是运行程序的一个实例，也是可以被指派到处理器上执行的实体。

It is a unit of activity: a sequence of instructions, a current state, and a set of system resources.

它是一个活动单位：一串指令的执行、一个当前状态和一组系统资源。

Its image contains the program, the data, the stack and the attributes in the process control block.

进程映像包含程序、数据、栈和进程控制块中的属性。

Q28 Briefly describe some of the errors that can happen in multi-process systems.简要说明多进程系统中可能出现的一些错误。 ▾

Improper synchronization: two processes use shared data at the same time, so updates are lost (a race condition).

同步不当：两个进程同时使用共享数据，导致更新丢失（竞争条件）。

Deadlock: two or more processes wait for each other forever and none can continue.

死锁：两个或多个进程互相等待，谁也无法继续。

Starvation: a process never gets the resource it needs because others always go first.

饥饿：某进程永远得不到所需资源，因为总是被别的进程抢先。

Protection errors: one process changes the memory or the files of another process.

保护错误：一个进程修改了另一个进程的内存或文件。

Q29 What are some of the responsibilities of memory management in a modern operating system?现代操作系统中存储器管理有哪些职责？ ▾

Keep track of which memory is used and by which process.

记录哪些内存被使用、被哪个进程使用。

Allocate memory to processes and take it back when they finish.

为进程分配内存，进程结束时收回内存。

Protect the memory of each process from the other processes.

保护每个进程的内存不被其他进程破坏。

Map virtual addresses to physical addresses and implement virtual memory with paging or segmentation.

把虚拟地址映射到物理地址，并用分页或分段实现虚拟存储器。

Swap processes in and out of main memory and allow memory to be shared when needed.

把进程换入/换出主存，并在需要时允许共享内存。

Q30 What are the main ideas behind virtual memory paging?虚拟存储器分页的主要思想是什么？ ▾

The program sees a large continuous virtual address space; the real physical memory can be smaller.

程序看到的是一个很大的连续虚拟地址空间，实际的物理内存可以更小。

Virtual memory is divided into fixed-size pages; physical memory is divided into frames of the same size.

虚拟存储器被划分为固定大小的页，物理内存被划分为同样大小的页框。

A page table maps every virtual page to a physical frame.

页表把每个虚拟页映射到物理页框。

Only the pages that are needed are kept in memory; if a page is missing a page fault happens and the operating system loads it from disk.

只有需要的页才放在内存中；缺页时产生缺页中断，操作系统把它从磁盘调入。

Q31 What are the main components of information system security?信息系统安全的主要组成部分有哪些？ ▾

Confidentiality: only authorized users may read the information.

机密性：只有被授权的用户才能读取信息。

Integrity: only authorized users may change the information, and only in an allowed way.

完整性：只有被授权的用户才能修改信息，而且只能按允许的方式修改。

Availability: authorized users can use the system and the data when they need them.

可用性：被授权的用户在需要时能够使用系统和数据。

Support mechanisms: identification and authentication, access control, and auditing/accountability.

支撑机制：身份识别与认证、访问控制，以及审计与可追责性。

Q32 What are the main priorities for the scheduling and resource management component of a modern operating system?现代操作系统的调度与资源管理部分主要考虑哪些目标？ ▾

Fairness: every process gets a fair share of the processor and of the resources.

公平性：每个进程都能公平地得到处理器和资源。

Efficiency and throughput: keep the processor and the devices as busy as possible.

效率与吞吐量：让处理器和设备尽可能忙碌。

Response time: interactive users must get a fast answer.

响应时间：交互用户必须很快得到响应。

Priority and deadlines: important or real-time work must be done first or in time.

优先级与截止时间：重要或实时的工作必须优先或按时完成。

Avoid starvation and keep the overhead of scheduling itself small.

避免饥饿，并使调度本身的开销尽量小。

Q33 Briefly explain the difference between control passing from a user process to the operating system through an interrupt and through a service call.说明通过中断和通过服务调用把控制权从用户进程交给操作系统的区别。 ▾

An interrupt is caused by an event outside the running instruction, for example I/O finished, a clock tick or an error; it is asynchronous.

中断由与当前指令无关的外部事件引起，例如 I/O 完成、时钟滴答或出错，它是异步的。

A service call (supervisor call) is an explicit request by the program to call an operating system function; it is synchronous.

服务调用（管态调用）是程序明确请求调用操作系统功能，它是同步的。

With an interrupt the processor reacts to the event; with a service call the program asks for a service such as reading a file.

中断时处理器是对事件作出反应；服务调用时程序主动请求服务，例如读取文件。

In both cases the processor switches to kernel mode and runs operating system code.

两种情况都会切换到内核态并执行操作系统代码。

Q34 Briefly describe the difference between a monolithic and a microkernel operating system.说明整体式（单内核）操作系统与微内核操作系统的区别。 ▾

Monolithic kernel: the whole operating system (scheduling, file system, device drivers, memory management) is one big program running in kernel mode.

整体式内核：整个操作系统（调度、文件系统、设备驱动、存储器管理）是在内核态运行的一个大程序。

It is fast because the parts call each other directly, but it is large, hard to maintain and a bug can stop the whole system.

它很快，因为各部分直接相互调用；但它很大、难维护，一个错误就可能使整个系统停止。

Microkernel: only the essential functions stay in kernel mode, for example interprocess communication, basic scheduling and basic memory management.

微内核：只有最基本的功能留在内核态，例如进程间通信、基本调度和基本存储器管理。

File systems and drivers run as separate user-level servers; this is more modular, safer and easier to extend, but messages cost more time.

文件系统和驱动作为独立的用户级服务器运行；这样更模块化、更安全、更易扩展，但消息传递要花更多时间。

Q35 Briefly explain the main ideas behind multithreading.简要说明多线程的主要思想。 ▾

A thread is one path of execution inside a process.

线程是进程内的一条执行路径。

Each thread has its own program counter, registers and stack.

每个线程有自己的程序计数器、寄存器和栈。

All threads of one process share the address space, the files and the other resources.

同一进程的所有线程共享地址空间、文件和其他资源。

Creating and switching threads is cheaper than for processes, and on a multicore computer threads really run at the same time.

线程的创建和切换比进程便宜，在多核计算机上线程可以真正同时运行。

It improves responsiveness: one thread can wait for I/O while another keeps computing.

它提高响应性：一个线程等 I/O 时，另一个线程可以继续计算。

Q36 Briefly explain the main four advantages of Symmetric Multiprocessing.简要说明对称多处理的四个主要优点。 ▾

Performance: if the work can be split, several processors do it at the same time and it is finished sooner.

性能：工作能拆分时多个处理器同时做，完成得更快。

Availability: if one processor fails the system keeps running, only with less power.

可用性：一个处理器故障时系统继续运行，只是能力下降。

Incremental growth: the user can add more processors to get better performance.

逐步扩充：用户可以增加处理器来获得更好的性能。

Scaling: the same software can run on machines with a different number of processors.

可扩展性：同一套软件可以在处理器数量不同的机器上运行。

Q37 How is a distributed operating system different from a SMP system?分布式操作系统与 SMP 系统有什么不同？ ▾

In an SMP system several processors share the same main memory and the same clock in one computer.

SMP 系统中多个处理器共享同一台计算机的主存储器和时钟。

In a distributed system there are several independent computers, each with its own memory and its own clock.

分布式系统中有多台独立的计算机，各有自己的内存和时钟。

Distributed computers talk by messages over a network; SMP processors talk through shared memory.

分布式计算机通过网络消息通信；SMP 的处理器通过共享内存通信。

A distributed operating system tries to make the collection of computers look like one single system; it is more scalable and more fault tolerant, but communication is slower.

分布式操作系统努力让这一组计算机看起来像一个系统；它可扩展性更好、容错性更好，但通信更慢。

Q38 In the context of fault tolerance, briefly explain reliability, MTTF, MTTR and Availability, and how they are measured.在容错方面，简要说明可靠性、MTTF、MTTR 和可用性，以及它们如何度量。 ▾

Reliability: how long a system works correctly without failing; measured as the probability of correct operation over a period of time (or as a failure rate).

可靠性：系统能正确工作多久而不出故障；用一段时间内正确运行的概率（或故障率）来度量。

MTTF (mean time to failure): the average time a system runs before it fails; measured by taking the average over many systems or many runs.

MTTF（平均无故障时间）：系统发生故障前平均能运行的时间；通过对多个系统或多次运行取平均得到。

MTTR (mean time to repair): the average time needed to find the fault and repair the system.

MTTR（平均修复时间）：找出故障并修复系统所需的平均时间。

Availability: the fraction of time the system is usable; availability = MTTF / (MTTF + MTTR).

可用性：系统可用的时间比例；可用性 = MTTF / (MTTF + MTTR)。

Q39 Give four different types of faults that could occur in a computer system.举出计算机系统中可能出现的四种不同类型的故障。 ▾

Permanent fault: the component is broken forever, for example a burnt-out chip or a disk head crash.

永久性故障：部件永久损坏，例如芯片烧毁或磁头损坏。

Transient fault: it happens once and then disappears, for example a power surge or a bit changed by an alpha particle.

瞬时故障：发生一次后消失，例如电涌或由 α 粒子翻转的一个比特。

Intermittent fault: it comes and goes again and again, for example a loose connector that fails when the machine is hot.

间歇性故障：反复出现又消失，例如接触不良的接插件在机器发热时才失效。

Software or design fault: a bug in the operating system or in a program, for example a wrong calculation or an infinite loop.

软件或设计故障：操作系统或程序中的错误，例如计算错误或死循环。

Source: “Ch02v2a.pdf” — original slides: p.57, p.58, p.59（点击链接可跳转查看原教材）
Q40 Faults can be either permanent or temporary. Temporary faults can be classified into two subtypes. What are they? Give an example of each.故障分为永久性和临时性。临时性故障又分两个子类，它们是什么？各举一例。 ▾

The two subtypes are transient faults and intermittent faults.

两个子类是瞬时故障与间歇性故障。

A transient fault happens once and does not come back, for example one memory bit changed by radiation or by a power spike.

瞬时故障只发生一次、不再重复，例如辐射或电压尖峰导致某个存储位被改变。

An intermittent fault comes back again and again, for example a bad solder joint or a loose cable that fails from time to time.

间歇性故障会反复出现，例如虚焊点或接触不良的线缆时好时坏。

Q41 Name three specific mechanisms how Microsoft Windows increases fault tolerance.举出 Microsoft Windows 提高容错性的三种具体机制。 ▾

NTFS is a recoverable file system: it keeps a transaction log, so after a crash the file system can be brought back to a correct state.

NTFS 是可恢复的文件系统：它保存事务日志，崩溃后可以把文件系统恢复到正确状态。

Structured exception handling and protected subsystems: an application that fails is stopped by itself and does not destroy the operating system.

结构化异常处理与受保护子系统：出错的应用程序只影响自己，不会破坏操作系统。

Automatic restart and recovery: after a serious system failure the machine restarts by itself and can boot the last known good configuration.

自动重启与恢复：严重系统故障后机器可自动重启，并使用“最后一次正确配置”启动。

Driver signing and driver verification: only checked drivers are loaded, so a bad driver does not crash the system.

驱动程序签名与验证：只加载经过检查的驱动，避免坏驱动使系统崩溃。
