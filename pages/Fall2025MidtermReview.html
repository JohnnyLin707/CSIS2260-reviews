Q1 · Process control block 4 marks / 4 分

EN · QUESTION
中文 · 题目
The Process Control Block is a key tool that enables the OS to support multiple processes and to provide support for multiprocessors. List FOUR elements that are in the process control block?
进程控制块（PCB）是操作系统支持多进程、并支持多处理器的重要工具。请列出进程控制块中的四个要素。

Answer · 参考答案（每点 1 分）

  • Identifier: a unique process identifier (PID) assigned to the process when it is created.标识符：进程创建时分配的唯一进程标识符（PID）。
  • State: the current state of the process (New, Ready, Running, Blocked, suspended, Exit).状态：进程当前所处的状态（新建、就绪、运行、阻塞、挂起、退出）。
  • Priority: the scheduling priority used by the dispatcher.优先级：分派程序使用的调度优先级。
  • Program counter: the address of the next instruction to be executed for this process.程序计数器：该进程下一条待执行指令的地址。

Other acceptable elements (any four earn full marks): memory pointers, context data, I/O status information and accounting information. The PCB is created and managed by the OS and holds the process elements.
其它同样可得分的要素：存储器指针、上下文数据、I/O 状态信息、记账信息。任写四个即可满分。

教材依据 / Source: Ch03v2a p.6 — Process Elements · Chapter 3 Review Q43 · p.33 Process Control Structures

Q2 · Why two execution modes? 4 marks / 4 分

EN · QUESTION
中文 · 题目
Why are two modes (user and kernel) needed?
为什么需要两种执行模式（用户态与内核态）？

Answer · 参考答案（每点 1 分）

  • Protect the OS and other processes: in user mode a program cannot execute privileged instructions (direct I/O, altering memory-management registers, halt), so a user job cannot damage the monitor, the kernel or another job.保护操作系统与其它进程：用户态下程序不能执行特权指令（直接 I/O、修改存储器管理寄存器、停机指令），因此用户作业无法破坏监控程序、内核或其它作业。
  • Memory protection: only kernel mode may access protected OS memory areas, OS tables and PCBs; user mode is restricted to its own address space.存储器保护：只有内核态能访问受保护的操作系统内存区、系统表与 PCB；用户态只能访问自己的地址空间。
  • Controlled entry into the OS: an interrupt, a trap/exception or a system call (supervisor call) switches the processor into kernel mode so that OS services run with full privilege, and then switches back to user mode.受控进入操作系统：中断、异常（陷阱）或系统调用会让处理器切换到内核态，使操作系统服务以完整特权运行，之后再返回用户态。
  • Safe sharing of the processor: the mode bit plus timers and interrupts let the OS regain control, stop one job from monopolising the CPU, and safely schedule many processes (and on multiprocessors, many CPUs).安全地共享处理器：模式位配合定时器与中断，使操作系统能收回控制权、防止某个作业独占 CPU，并安全地调度多个进程（在多处理器上调度多个 CPU）。

User mode = less privileged, user programs run here. Kernel (system/control) mode = more privileged, the OS kernel runs here and may execute privileged instructions and access protected memory.
用户态特权较低，用户程序在此运行；内核态（系统态／控制态）特权较高，操作系统内核在此运行，可执行特权指令并访问受保护内存。

Q3 · Resources shared by threads 4 marks / 4 分

EN · QUESTION
中文 · 题目
What resources are typically shared by all threads of a process?
一个进程中的所有线程通常共享哪些资源？

Answer · 参考答案（每项 1 分，共 4 分）

  • The virtual address space that holds the process image.容纳进程映像的虚拟地址空间。
  • The user address space (one per process, shared by every thread).用户地址空间（每个进程一个，由所有线程共享）。
  • The process control block (PCB) — in the multithreaded model there is only one PCB per process.进程控制块（PCB）—— 多线程模型中每个进程只有一个 PCB。
  • The user program / executable code (text) of the process.进程的用户程序／可执行代码（代码段）。
  • User data and global / static variables in the process image.进程映像中的用户数据与全局／静态变量。
  • The heap / dynamically allocated memory inside that address space.该地址空间中的堆／动态分配内存。
  • Memory pointers and memory-management tables (page/segment tables) for the process.进程的存储器指针与存储器管理表（页表／段表）。
  • Protected access to processors — the process is the unit of resource allocation and protection.对处理器的受保护访问 —— 进程是资源分配与保护的单位。
  • Protected access to files — open files and file descriptors / file tables.对文件的受保护访问 —— 已打开的文件、文件描述符与文件表。
  • Protected access to I/O resources (devices and channels) and the I/O status information.对 I/O 资源（设备与通道）的受保护访问，以及 I/O 状态信息。
  • Protected access to other processes — interprocess communication resources such as shared memory, pipes, message queues and semaphores.对其它进程的受保护访问 —— 共享内存、管道、消息队列、信号量等进程间通信资源。
  • The process identifier and credentials (PID, parent PID, user / group IDs).进程标识符与凭证（PID、父进程 PID、用户／组标识）。
  • Process-level state and priority (scheduling information held at process level).进程级的状态与优先级（进程层的调度信息）。
  • Accounting information and resource ownership / utilisation recorded by the OS.操作系统记录的记账信息，以及资源拥有与使用情况。

Important contrast: each thread has its OWN program counter, execution state, saved thread context, execution stack, per-thread static storage for local variables, user stack, kernel stack and thread control block (TCB) — these are NOT shared. All threads of a process share the memory and resources of that process.
易错点：每个线程各自拥有程序计数器、执行状态、保存的线程上下文、执行栈、局部变量静态存储、用户栈、内核栈与线程控制块（TCB），这些不共享；共享的是进程的内存与资源。

Q4 · ULT and KLT 4 marks / 4 分

EN · QUESTION
中文 · 题目
Define and explain ULT and KLT.
定义并说明 ULT（用户级线程）与 KLT（内核级线程）。

ULT · User-Level Thread 用户级线程（2 分）

  • Definition: all thread management is done by the application; a threads library creates, destroys and schedules threads, the kernel is not aware that threads exist and schedules the process as a single unit.定义：所有线程管理工作都由应用程序完成，线程库负责创建、销毁与调度；内核不知道线程的存在，只以进程为单位进行调度。
  • Advantages: thread switching does not need kernel-mode privileges; scheduling can be application-specific; ULTs can run on any OS.优点：线程切换不需要内核态特权；调度方式可按应用定制；ULT 可运行于任何操作系统。
  • Disadvantages: when one ULT makes a blocking system call, all threads of the process are blocked; a pure ULT strategy cannot exploit multiprocessing because the kernel assigns one process to only one processor at a time.缺点：某个 ULT 执行阻塞式系统调用时，进程内所有线程都会被阻塞；纯 ULT 无法利用多处理器，因为内核一次只把进程分配给一个处理器。

KLT · Kernel-Level Thread 内核级线程（2 分）

  • Definition: thread management is done by the kernel; there is no thread-management code at application level, only an API to the kernel thread facility (Windows is an example).定义：线程管理由内核完成，应用层没有线程管理代码，只有调用内核线程机制的 API（Windows 即为例子）。
  • Advantages: the kernel can schedule multiple threads of the same process on multiple processors at the same time; if one thread blocks, the kernel can schedule another thread of the same process; kernel routines themselves can be multithreaded.优点：内核可把同一进程的多个线程同时调度到多个处理器；某个线程阻塞时，内核可调度同进程的另一线程；内核例程本身也可多线程化。
  • Trade-off: every thread switch goes through the kernel, so it costs a mode switch (slower than a pure user-level switch).代价：每次线程切换都要经过内核，需要模式切换，比纯用户级切换慢。

Q5 · Seven-state process transition diagram 7 + 3 = 10 marks / 10 分

EN · QUESTION
中文 · 题目
Draw the state transition diagram for the SEVEN different states of a process (7 marks) — use a CIRCLE for each of the seven states. Use ARROWS to describe the transition from each state to another (3 marks).
画出进程七种状态的状态转换图（7 分）—— 每种状态用一个圆圈表示；用箭头描述各状态之间的转换（3 分）。

Part 1 · Seven states (one circle each) 七个状态

Part 1 · What each circle means 各状态含义

  • New: the process has just been created and has not yet been admitted to the set of executable processes.新建：进程刚被创建，尚未被接纳进可执行进程集合。
  • Ready: the process is in main memory and is waiting for a chance to run.就绪：进程已在主存中，等待被调度执行。
  • Running: its instructions are being executed by the processor.运行：其指令正被处理器执行。
  • Blocked: it cannot execute until an event occurs (for example an I/O completion).阻塞：必须等到某事件发生（例如 I/O 完成）才能执行。
  • Ready/Suspend: a ready process has been swapped out to disk; it can run as soon as it is loaded back into main memory.就绪／挂起：就绪进程被换出到磁盘；调回主存后即可运行。
  • Blocked/Suspend: a blocked process has been swapped out to disk and is still waiting for its event.阻塞／挂起：被阻塞的进程被换出到磁盘，且仍在等待事件。
  • Exit: the process has halted or aborted and has been released by the OS.退出：进程已停止或被中止，并被操作系统释放。

Part 2 · Labelled arrows (3 marks) 转换箭头

  • Admit: New → Ready (or New → Ready/Suspend when main memory is full).接纳：新建 → 就绪（主存不足时新建 → 就绪／挂起）。
  • Dispatch: Ready → Running; Timeout: Running → Ready when the time slice ends.分派：就绪 → 运行；超时：时间片用完，运行 → 就绪。
  • Event Wait: Running → Blocked; Event Occurs: Blocked → Ready.事件等待：运行 → 阻塞；事件发生：阻塞 → 就绪。
  • Release: Running → Exit (also possible from Ready, Blocked and the suspended states).释放：运行 → 退出（就绪、阻塞及挂起态也可被终止）。
  • Suspend: Ready → Ready/Suspend, Blocked → Blocked/Suspend, Running → Ready/Suspend.挂起：就绪 → 就绪／挂起，阻塞 → 阻塞／挂起，运行 → 就绪／挂起。
  • Activate: Ready/Suspend → Ready, Blocked/Suspend → Blocked; Event Occurs: Blocked/Suspend → Ready/Suspend.激活：就绪／挂起 → 就绪，阻塞／挂起 → 阻塞；事件发生：阻塞／挂起 → 就绪／挂起。

Q6 · Linux commands 10 marks / 10 分

EN · QUESTION
中文 · 题目
Assume the file ex2 contains three records: Mary, Jack, Alice. Write the command for each of the tasks below.
假设文件 ex2 中有三条记录：Mary、Jack、Alice。写出完成下列每个任务的命令。

The tasks below are given as clean, executable commands taken from the course handout and Lab 8. Task 0 reproduces the file setup stated in the question, so the ten marks are accounted for.
下列任务均按课程讲义与 Lab 8 给出可直接执行的命令；第 0 题还原题干中的文件准备过程，合计 10 分。

Answer · 参考答案（每题 1 分）

  • 0. Create ex2 with the three records (setup): cat > ex2 then type Mary / Jack / Alice, one per line, and press Ctrl+D.准备：建立含三条记录的 ex2 —— cat > ex2，逐行输入 Mary / Jack / Alice，最后按 Ctrl+D 结束。
  • a. Display the file ex2: cat ex2显示 ex2 的全部内容：cat ex2（也可用 more ex2、less ex2）。
  • b. Display the first 2 lines of ex2: head -n 2 ex2 (equivalently head -2 ex2).显示 ex2 的前 2 行：head -n 2 ex2（等价于 head -2 ex2）。
  • c. Display the last 2 lines of ex2: tail -n 2 ex2 (equivalently tail -2 ex2).显示 ex2 的最后 2 行：tail -n 2 ex2（等价于 tail -2 ex2）。
  • d. Search ex2 for the word Jack: grep Jack ex2在 ex2 中搜索单词 Jack：grep Jack ex2。
  • e. Append one more record to ex2 (here David is used as the example record): cat >> ex2, type David, then Ctrl+D (one-line alternative: echo David >> ex2).向 ex2 追加一条记录（这里以 David 为例）：cat >> ex2 后输入 David 并按 Ctrl+D；单行写法为 echo David >> ex2。
  • f. Using a pipe, count how many files in your home directory start with the characters "ex": ls | grep '^ex' | wc -l (the Lab 8 form is ls -l | grep '^ex' | wc -l).用管道统计主目录中以 ex 开头的文件数：ls | grep '^ex' | wc -l（Lab 8 写法为 ls -l | grep '^ex' | wc -l）。
  • g. Create a directory called "Windows 11": mkdir "Windows 11" (if the name has no space: mkdir windows11).建立名为 Windows 11 的目录：mkdir "Windows 11"；若名称不含空格则 mkdir windows11。
  • h. Create a subdirectory called "games" inside it: mkdir "Windows 11/games" (or cd "Windows 11" then mkdir games).在其中建立子目录 games：mkdir "Windows 11/games"；也可先 cd "Windows 11" 再 mkdir games。
  • i. Get help on the command tail: man tail (short description: whatis tail; find related commands: apropos tail).查看 tail 命令的帮助：man tail；一行简介用 whatis tail，查找相关命令用 apropos tail。
